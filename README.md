# LocalHttpDaemon

Windows上でHTMLや画像などのファイルをブラウザから確認するための簡易ウェブサーバーです。コマンドラインで操作するCLI版と、画面で操作するGUI版があります。

## 共通の機能

- 指定したルートフォルダ内のHTML、CSS、JavaScript、画像などをHTTP・HTTPSで配信します。
- アプリケーションが動作している間だけ待ち受けます。同じPCの `localhost` から利用するローカル用途です。
- 既定ポートはHTTPが **80**、HTTPSが **443** です。保存済み設定がある場合は、そのポートを使用します。
- GET・HEADに対応します。POSTなどの未対応メソッドには405、存在しないファイルには404を返します。
- `/` やフォルダへのアクセスでは、そのフォルダの `index.html` を返します。ファイルの一覧表示やサーバー側プログラムの実行機能はありません。
- 配布用EXEはWindows x64向けです。.NETランタイムを別途インストールする必要はありません。

## はじめに

1. 使用する版のZIPを展開し、EXEを設定ファイルの保存が可能なフォルダに置きます。
2. 配信用フォルダを用意し、`index.html` などのファイルを入れます。以下では `D:\WebRoot` を例にします。
3. CLI版またはGUI版でサーバーを開始します。
4. ブラウザで `http://localhost/` または `https://localhost/` を開きます。例えば `D:\WebRoot\images\sample.png` は `/images/sample.png` から参照できます。

配布ファイルは次の場所にあります。

| 版 | ZIP | 実行ファイル |
| --- | --- | --- |
| CLI | `CLI_LocalHttpDaemon_Package/CLI_LocalHttpDaemon-win-x64.zip` | `CLI_LocalHttpDaemon.exe` |
| GUI | `GUI_LocalHttpDaemon_Package/GUI_LocalHttpDaemon-win-x64.zip` | `GUI_LocalHttpDaemon.exe` |

## CLI版の使い方

PowerShellなどのターミナルで、EXEを置いたフォルダから実行します。

```powershell
.\CLI_LocalHttpDaemon.exe --root "D:\WebRoot"
```

初回はルートフォルダを絶対パスで指定します。パスに空白がある場合は引用符で囲んでください。フォルダ区切りは `\` と `/` の両方が使用できます。

起動すると、ルートフォルダとアクセス先が表示されます。

```text
ROOT : D:\WebRoot
HTTP : http://localhost:80/
HTTPS: https://localhost:443/
```

終了するにはターミナルで **Ctrl+C** を押します。

### コマンドラインオプション

| オプション | 内容 |
| --- | --- |
| `--root <絶対パス>` | 配信用のルートフォルダを指定します。 |
| `--port <HTTP>[/<HTTPS>]` | HTTP・HTTPSのポートを指定します。HTTPSを省略するとHTTPのみ変更します。 |
| `--help` / `-h` | ヘルプを表示して終了します。 |

HTTP・HTTPSの両方を変更する例：

```powershell
.\CLI_LocalHttpDaemon.exe --root "D:\WebRoot" --port 8080/8443
```

この場合のアクセス先は `http://localhost:8080/` と `https://localhost:8443/` です。

HTTPだけを変更する例：

```powershell
.\CLI_LocalHttpDaemon.exe --port 8080
```

`--port 8080/` も同じ意味です。HTTPSは保存済みの値、保存済み設定がなければ443を使用します。各ポートには1〜65535の異なる番号を指定してください。

起動可能な設定はEXEと同じ場所の `settings.json` に保存されます。次回以降は次のように引数なしで起動できます。

```powershell
.\CLI_LocalHttpDaemon.exe
```

設定の優先順位は **コマンドラインの指定 → settings.json → 既定値** です。引数で変更した設定も保存されます。ルートが引数にも設定ファイルにもない場合は、指定を促す案内とヘルプを表示して終了します。

## GUI版の使い方

1. `GUI_LocalHttpDaemon.exe` を起動します。
2. 「ルートフォルダの絶対パス」に配信用フォルダを入力します。「パス指定」ボタンでも選択できます。
3. 「HTTPのポート番号」と「HTTPSのポート番号」を確認します。初回の既定値は80と443です。
4. 「実行」を押すと、HTTP・HTTPSの待ち受けを開始します。動作中は設定欄が無効になり、ボタンが「停止」に変わります。
5. ブラウザからアクセスします。ポートを変更した場合は、URLに `:8080` などを付けます。
6. 「停止」を押すと待ち受けを終了し、設定を変更できるようになります。ウィンドウを閉じた場合も停止します。

設定はEXEと同じ場所の `settings.json` に保存され、次回起動時に入力欄へ復元されます。**GUI版は起動しただけでは待ち受けを開始しません。「実行」を押してください。**

「▼ログ表示」を押すとアクセスログを表示し、「▲ログ隠蔽」で隠します。非表示中も記録し、最新1000件を保持します。停止・再実行では履歴を維持し、アプリ終了時に破棄します。

## アクセスログの見方

CLI版はコンソールに、GUI版はログ欄に、次の形式で表示します。

```text
[GET] 2026/10/26 12:30 200 index.html
[GET] 2026/10/26 12:31 404 missing.html
[POST] 2026/10/26 12:32 405 /
```

左からメソッド、アクセス時刻、応答結果、要求パスです。処理エラーでは末尾に詳細を表示し、応答結果がない場合は `ERROR` と表示します。

| 色 | 主な意味 |
| --- | --- |
| 白 | 成功した通常のGET |
| 赤 | 404、サーバー処理・通信・HTTPS接続のエラーなど |
| 黄 | HEAD・POSTなどGET以外のアクセス、リダイレクト応答 |

処理エラーや404・500以上は赤が優先されます。POSTの405は黄色です。リダイレクト応答自体を生成する機能はありません。ログのファイル保存は行いませんが、CLI版はシェルで標準出力をファイルにリダイレクトできます。

## CLI版・GUI版で設定を共用する

両版の `settings.json` は同じ形式です。EXEと同じフォルダに配置することで、相互に使用できます。別々のフォルダにEXEを置く場合は、設定ファイルをコピーしてください。

```json
{
  "RootPath": "D:\\WebRoot",
  "HttpPort": 80,
  "HttpsPort": 443
}
```

通常はアプリの操作で保存できるため、手作業で編集する必要はありません。既存設定のHTTPSポートが8080などの場合、EXEを更新してもその値は維持します。443へ変更する場合は、CLI版で `--port 80/443` を指定するか、GUI版のポート欄を変更して「実行」を押してください。

両版を同時に動作させる場合は、使用するポートが重ならないようにしてください。同じ場所の設定を共用している場合、一方で保存した値は、もう一方の次回起動時に読み込まれます。

## 起動やアクセスに困ったとき

- **HTTPSで証明書の警告が出る**：localhost用の自己署名証明書を使用するためです。証明書は初回に作成して再利用します。内容確認にHTTPSが不要ならHTTPでアクセスできます。
- **ポートを開けない**：別のアプリが使用していないか、実行権限に制限がないか確認してください。必要に応じて8080/8443などへ変更します。
- **設定を保存できない**：EXEを置いたフォルダへの書き込み権限を確認してください。設定保存に失敗した場合はサーバーを開始しません。
- **404になる**：指定ルート配下に対象ファイルがあるか確認してください。ルートURLでは `index.html` が必要です。
- **別のPCから接続できない**：同じPCのlocalhost専用です。LANやインターネットからの接続は受け付けません。
