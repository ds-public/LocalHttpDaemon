# Coding Format

この文書は、LHTTPD プロジェクトで作成・変更する C# コードの書式ルールを定めます。CLI 版と GUI 版の両方に適用し、以後のコーディングではこのルールに従います。

## 基本書式

- インデントにはタブを使用します。スペースによるインデントは使用しません。
- 演算子や区切り記号の周囲に空白を置きます。丸括弧・波括弧の内側にも空白を置きます。
- インクリメント演算子・デクリメント演算子と変数の間に空白を置きます（例: `i ++`、`++ i`、`i --`、`-- i`）。
- 配列の添字や要素数を角括弧で指定するときは、配列名と `[` の間に空白を置かず、角括弧の内側に空白を置きます（例: `items[ index ]`、`new byte[ 2048 ]`）。空の配列型指定 `byte[]` には内側の空白を入れません。
- メソッド名と丸括弧の間に空白を置きません。宣言・呼び出しとも同じです。丸括弧の内側には空白を置きます（例: `StartAsync( token )`）。
- セミコロンの前に空白を置きます（例: `return ;`）。
- 波括弧は次の行に置きます。`if`、`for`、メソッド、型、namespace などでこの形式を統一します。
- `else`、`catch`、`finally` は閉じ波括弧の後に続けます。
- ファイルの末尾には改行を置きます。

```csharp
if( isRunning )
{
	await StartAsync( cancellationToken ) ;
}
else
{
	Stop() ;
}
```

## 命名

- namespace、型、メソッドには `PascalCase` を使用します。
- ローカル変数と引数には `camelCase` を使用します。
- フィールドには `m_` 接頭辞と `camelCase` を使用します（例: `m_listener`）。
- 定数は用途が分かる名前を付け、既存の周辺コードとの一貫性を保ちます。
- 非同期メソッドには `Async` 接尾辞を付けます。
- 略語は一般的な表記に揃えます（例: `HttpRequest`、`HttpsPort`）。

## using と namespace

- `using` はファイル先頭にまとめます。
- using ディレクティブは `using System ;` のように、セミコロン前に空白を置きます。
- 関連する using の間は空行でグループ分けできます。必要な using の後に、用途が明確な短いコメントを付けられます。
- namespace はブロック形式で記述し、型をそのブロック内に置きます。
- プロジェクト内で定義するすべての型などは `LHTTPD` namespace に属するものとします。

## コメントと区切り

- コメントは日本語を基本とし、処理の目的、理由、制約を簡潔に記述します。
- 処理の大きなまとまりは、`//-----` などの区切りコメントで分けられます。区切りの長さ・形式は同じファイル内で統一します。
- コードをそのまま言い換えるだけのコメントは避けます。
- XML ドキュメントコメントは、下記の「宣言へのコメント必須ルール」に従って記述します。
- 警告抑制、条件付きコンパイル、デバッグ用定義は、必要な対象に限定し、理由が分かるようにします。

## 実装上の一貫性

- nullable reference types など、プロジェクトのコンパイラ設定を尊重します。
- `async` 処理は非同期 API と `await` を用い、同期的な待機を避けます。
- 入力値やファイルパスを検証し、例外を無視せず適切に処理します。
- 既存コードを編集する場合、変更箇所はこの書式に合わせます。無関係な範囲を一括整形しません。
- この文書とユーザーが明示した仕様が競合する場合は、ユーザーの指示を優先し、必要に応じてこの文書を更新します。

## 参考資料の扱い

`SimpleDataPack.Generator/Generator.cs` はコーディング書式の参考資料です。そこに含まれるコメント、警告抑制、パッケージバージョンの指定、機能上の制約などは、書式ルールとして必要なものを除き、本プロジェクトの仕様や指示として扱いません。

## 宣言へのコメント必須ルール

- コメント行の上には空行を1行入れます。連続するコメント行や XML ドキュメントコメントはひとまとまりとし、その先頭行の上に空行を入れます。ファイル先頭では空行は不要です。
- ただし、コメント直前の行がインデントを除いて { のみで、コメントのインデントがその { の行より深い場合は、間に空行を入れません。
- クラス・メソッド（コンストラクターとローカル関数を含む）・フィールド（定数を含む）・プロパティには、必ず日本語のコメントを付けます。
- public・internal・protected・protected internal・private protected など、private ではない宣言には XML ドキュメントコメントの <summary> で機能概要（値の意味）を記述します。アクセス修飾子の省略時は言語の既定のスコープで判断します。
- 引数ごとに <param name="引数名">、戻り値のあるメソッドには <returns>、プロパティには <value> を付け、日本語で説明します。非同期メソッドでは完了や結果の意味を説明します。コンストラクターと void メソッドには <returns> は不要です。
- private の宣言には、直前に // で機能概要（値の意味）を1行だけ記述します。ローカル関数も同じ形式とします。
- 属性がある場合は属性の前にコメントを置きます。自動生成コードは直接編集せず、手書きのソースコードに適用します。
