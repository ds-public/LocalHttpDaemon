# CLI版アプリケーション仕様

## 起動とヘルプ

- `--root <絶対パス>` でHTML等の配信ルートを指定する。区切りは `\` と `/` の両方に対応する。
- 引数にも保存済み設定にもルートがない場合、`--root` による指定を促す案内とオプションのヘルプをコンソールに表示し、待ち受けを開始せず終了コード0で終了する。作業フォルダを配信ルートには使用しない。
- `--help` / `-h` は設定の読み込み・保存や待ち受けを行わず、ヘルプを表示して正常終了する。
- 不明な引数、値の不足、不正なパス、存在しないフォルダ、不正なポートは終了コード2とする。

- 起動成功時のルート表示は `ROOT : <絶対パス>` とする。続けてHTTP・HTTPSのURLと終了方法を表示する。

## 設定の保存と優先順位

- `CLI_LocalHttpDaemon.exe` と同じ場所の `settings.json` を読み込む。作業フォルダや単一ファイルEXEの一時展開先には依存しない。
- GUI版と同じ設定クラスを使用し、次のJSONを相互利用できる。既定ポートはGUI版と同じHTTP 80・HTTPS 443とする。保存済み設定が8080など別の番号の場合は、その値を維持する。

```json
{
  "RootPath": "D:\\WebRoot",
  "HttpPort": 80,
  "HttpsPort": 443
}
```

- 優先順位はコマンドライン、保存済み設定、CLIの既定値（HTTP 80、HTTPS 443、ルート未指定）の順とする。
- `--port <HTTP>[/<HTTPS>]` に対応する。`--port 80` と `--port 80/` はHTTPのみ更新する。HTTPSは保存済み値、なければ443を維持する。
- 有効なポートは1〜65535で、HTTPとHTTPSには異なる値を指定する。
- 設定ファイルを読み込めない場合は理由を標準エラー出力に表示し、CLIの既定値を使用する。引数で有効な設定を指定すれば起動できる。
- ルートの検証・証明書の準備・両ポートの待ち受け開始に成功した時点で、設定が未保存または値が異なる場合に保存する。同じ値ならファイルを書き直さない。
- 設定保存はGUI版と同じ一時ファイルからの置換方式とする。保存に失敗した場合は理由を表示し、両方の待ち受けを停止して終了コード1で終了する。

## アクセスログ

- 応答結果が確定したアクセスと通信・TLS・ファイル処理エラーを表示する。サーバー終了に伴うキャンセルや、リクエストを送らず切断した接続は表示しない。
- GUI版と同じ形式で、`[メソッド] yyyy/MM/dd HH:mm 結果 パス` とする。例：`[GET] 2026/10/26 12:30 200 index.html`。
- 結果はHTTPステータスコード、応答前の処理エラーは `ERROR`。エラー詳細は ` — 詳細` として末尾に付加する。
- パス先頭の `/` は省略し、ルートへのアクセスのみ `/` を表示する。制御文字は空白に置換して1件を1行に収める。
- 色の優先順位はGUI版と同じとする。処理エラー・404・500以上は赤。次にGET以外または300〜399は黄。残りの400以上は赤、それ以外のGETは白。POST等の405応答とHEADは黄。
- 並行アクセスでも1行と色が混ざらないよう排他し、表示後はコンソールの元の色に戻す。出力をリダイレクトした場合も同じログ文字列を出力する。
- この変更ではリダイレクト応答やPOSTの処理自体は追加しない。

その他のHTTP/HTTPS応答、Ctrl+Cによる終了、自己完結型EXEの配布仕様は `アプリケーション基本仕様.md` と `ソリューション構成・ビルド仕様.md` に従う。
