# GUI 版 簡易ウェブサーバー仕様

## 対象と構成

- GUI 専用仕様。コンソール版は変更しない。
- ソリューション: `LocalHttpDaemon.slnx`。
- WPF / .NET 10 / Windows x64。C# は `Documents/CodingFormat.md`（ソリューションルート基準） に準拠する。

## 画面・操作

- 通常のメインウィンドウは1つ。幅480 DIP、高さは内容に合わせて自動決定し、サイズ変更は不可。
- 「ルートフォルダの絶対パス」ラベルと空の入力欄、その右に「パス指定」ボタンを配置する。
- パス欄はコピー・貼り付け可能。フォーカス時のIMEは既定でオフとし、日本語入力への切り替えも可能。
- 「パス指定」はWindows標準のフォルダ選択ダイアログを開き、確定時のみ選択パスを反映する。
- 「HTTPのポート番号」の既定値は80、「HTTPSのポート番号」の既定値は443。
- ポート欄は半角数字のみ入力・貼り付け可能、最大5桁。IMEを無効にする。
- 「実行」で入力を検証し、HTTPとHTTPSの両方を開始する。
- 検証順はルートフォルダ、HTTPポート、HTTPSポート。同時にすべてのエラーは表示せず、最初のエラーをダイアログで通知して該当欄へフォーカスする。
- ルートは必須かつ存在する絶対パス。各ポートは必須で1～65535、HTTPとHTTPSは異なる値。
- 証明書準備・ポート確保などに失敗した場合もエラーダイアログを表示する。片方だけ開始した状態は残さない。
- 開始成功時のみボタンを「停止」にし、パス欄・パス指定ボタン・両ポート欄をWindows標準の無効表示にする。
- 「停止」で通信を停止し、入力を有効化して「実行」に戻す。操作中は実行ボタンの多重操作を防ぐ。
- ウィンドウ終了時もサーバーと処理中の接続を停止する。再実行可能。

## 入力設定の保存・復元

- GUI版のHTTPS既定ポートを8080から443に変更する。HTTPは80。保存済み設定がある場合は保存値を優先し、旧設定の8080もそのまま復元する。
- 「実行」ボタンで入力検証に成功した後、待ち受け開始前に、EXEと同じフォルダの `settings.json` へ3項目を保存する。「停止」操作では保存しない。
- UTF-8 JSON形式で `RootPath`（文字列）、`HttpPort`（数値）、`HttpsPort`（数値）を記録する。パスは検証済みの絶対パスとして保存する。
- 設定保存が成功してもポート競合等で開始に失敗することがある。その場合も保存済み設定は保持する。
- 次回起動時に3項目を入力欄へ復元する。自動でサーバーを開始しない。
- ファイルがない場合はルート欄を空、HTTPを80、HTTPSを443として起動する。
- JSON破損・不正なポート・読み込み失敗の場合はダイアログで通知し、既定値で起動する。保存されたフォルダが現在存在しなくても欄に復元し、「実行」時に存在確認する。
- 保存先に書き込めない場合はダイアログで通知し、サーバーを開始しない。設定は一時ファイル経由で置換して更新する。
- 配布ZIPに利用者の `settings.json` は含めない。EXEを更新しても既存設定を上書きしない。

## アクセスログ

- 「実行／停止」と同じ行の左側に「▼ログ表示」ボタンを追加する。
- 初期状態はログ領域を非表示とする。押すとウィンドウ上端と幅を維持して下方向へ高さを約2倍に拡張し、下部にログ一覧を表示する。
- 表示中のボタンは「▲ログ隠蔽」とし、再度押すとログ一覧を非表示にして元の高さへ戻す。
- ウィンドウは引き続き固定サイズで、ユーザーによる任意のリサイズは不可。
- ログ背景は黒。成功した通常GETの行は白、404・サーバー処理エラーは赤、GET以外のアクセス（HEAD・POST等）は黄色で表示する。メソッド・時刻・パスを個別に色分けせず、行全体を同じ色にする。
- 色の優先順位は処理例外・404・5xxが赤、GET以外または3xxが黄色、その他の4xxが赤、それ以外が白。POSTへの405は黄色になる。
- リダイレクトは要求メソッドではなく3xx応答を指す。3xxの色分類は黄色とするが、今回リダイレクト応答機能自体は追加しない。転送後のGETだけから転送の有無は判別しない。
- 通信・ファイル処理・TLS接続失敗・タイムアウトのエラーは赤で記録し、エラー内容を末尾に付記する。応答ステータスがない場合は `ERROR`、メソッドやパスが取得できない場合は `[ERROR]` と `/` を表示する。通常の停止によるキャンセルや要求前の正常切断は記録しない。
- ログ一覧は内容量に応じて縦スクロールバーを表示する。長いパスは横スクロールで確認できる。
- HTTP／HTTPSで受信したGET・HEAD・POST等の各要求について、処理終了時に結果を1行で記録する。POST等の処理自体は引き続き未対応で405を返す。
- 表示書式は `[メソッド] yyyy/MM/dd HH:mm ステータス パス`。時刻はアクセス受信時のWindowsローカル時刻（24時間表記）。例: `[GET] 2026/10/26 16:43 200 Resources/Wall_Normal.png`。
- パスは要求URLからクエリとフラグメント、先頭の `/` を除いたもの。ルート要求は `/` と記録する。URLのパーセント表記はそのまま保持し、制御文字は空白に置き換える。
- 古い順から新しい順に表示し、最新1000件をメモリに保持する。1000件を超える場合は最古の1件を削除して追加する。
- ログ非表示中も記録を継続する。表示切り替えやサーバーの停止・再実行で履歴を消去しない。アプリ終了時に破棄し、ファイル保存は行わない。
- ログ表示切り替えはサーバーの開始・停止状態にかかわらず使用できる。

## 配信動作

- コンソール版と同じくIPv4 loopbackで待ち受けるローカル用途。URLは `http://localhost:80/` および `https://localhost/`（既定値）。
- HTTP/1.1応答。GET・HEADに対応し、その他のメソッドには405を返す。
- `/` とディレクトリ要求では `index.html` を配信する。ファイルがなければ404。
- HTML、CSS、JavaScript、JSON、テキスト、画像等の拡張子からContent-Typeを設定する。
- ルート外へのパストラバーサル、ルート配下の再解析ポイント経由の参照、代替データストリームへの参照を拒否する。
- 接続ごとに応答後切断。ヘッダー上限32KiB、接続処理のタイムアウト30秒。
- HTTPSはTLS 1.2/1.3。初回にlocalhost用自己署名証明書を作成し、`%LOCALAPPDATA%/LHTTPD/GUI/localhost.pfx` に保存して再利用する。
- Windows TLSで使用できるようユーザーの秘密鍵ストアを使用する。証明書を信頼済みストアへ自動登録しないため、ブラウザに信頼警告が出る場合がある。
- ポート競合や権限制約で開始できない場合は、ポート番号やアクセス権の確認を促す。

## ビルド・配布

```powershell
dotnet build LocalHttpDaemon.slnx -c Release
```

- 自己完結型・単一EXE。配布先に.NETランタイムの別途インストールは不要。
- Visual Studio 2026 の Release ビルド（再ビルドを含む）、または上記コマンドで、通常のビルド後に単独EXEの発行と配布ZIPの作成を自動実行する。Debug ビルドとデザイン時ビルドでは生成しない。
- 単独EXE: `GUI_LocalHttpDaemon_Package/win-x64/GUI_LocalHttpDaemon.exe`。
- ZIPには単独EXEと、本仕様書を複製した `README.md` を格納する。生成済みの配布物は上書き更新する。
- Visual Studio の高速な最新状態判定を無効にし、ソース変更がない Release ビルドでも配布物を再生成する。
- 発行処理はビルド済み成果物を使用し、ビルドの再帰呼び出しを防止する。検証用ビルド等で配布生成が不要な場合は `-p:SkipReleasePackage=true` を指定できる。
- 発行先の `GUI_LocalHttpDaemon.exe` を起動する。初回起動時にネイティブライブラリの一時展開が行われる場合がある。
- 配布ZIP: `GUI_LocalHttpDaemon_Package/GUI_LocalHttpDaemon-win-x64.zip`。
- 検証コード: `GUI_LocalHttpDaemon_Verification`。`dotnet run --project GUI_LocalHttpDaemon_Verification/GUI_LocalHttpDaemon_Verification.csproj -c Release` で実行する。
- 実行検証済み: 既定値、開始・停止の入力有効状態、HTTP/HTTPSのGET・HEAD・404・405、停止時のポート解放、ポート競合時の開始取り消し、再実行、ウィンドウ終了時のポート解放。
