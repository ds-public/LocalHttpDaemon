# ソリューション構成・ビルド仕様

## 構成

GUI 版のソリューションと Git リポジトリを引き継ぎ、`LocalHttpDaemon/` を Git・ソリューション・Codex プロジェクト共通のルートとする。以下のパスは、特記がない限りソリューションルートからの相対パス。仕様書はルート直下の `Documents/` に配置する。

```text
LocalHttpDaemon/
	.git/
	.vs/
	CLI_LocalHttpDaemon/
		CLI_LocalHttpDaemon.csproj
	CLI_LocalHttpDaemon_Package/
	CLI_LocalHttpDaemon_Verification/
		CLI_LocalHttpDaemon_Verification.csproj
	GUI_LocalHttpDaemon/
		GUI_LocalHttpDaemon.csproj
	GUI_LocalHttpDaemon_Package/
	GUI_LocalHttpDaemon_Verification/
		GUI_LocalHttpDaemon_Verification.csproj
	Documents/
	AGENTS.md
	.editorconfig
	.gitattributes
	.gitignore
	LocalHttpDaemon.slnx
```

- ソリューションには両アプリと両検証プロジェクトを登録する。
- 開発指針の AGENTS.md は LocalHttpDaemon 直下に配置し、Documents/ を相対パスで参照する。親の LHTTPD 直下には AGENTS.md を置かない。Codex の対象フォルダ切り替えはユーザーが行う。
- CLI は .NET 10、GUI は WPF / .NET 10 Windows。両アプリは独立した EXE とし、GUI / CLI の起動モード切り替えは追加しない。
- 既存 GUI 版の Git 履歴、設定ファイル、配布先の `settings.json` を保持する。
- ファイル名は `.editorconfig`、`.gitattributes`、`LocalHttpDaemon.slnx` に統一する。
- 仕様書の参照と配布用 README のコピー元は `Documents/` に合わせる。
- ソース・設定・文書は LF 改行とし、インデントはタブを使用する。

## ビルドと配布

ソリューションルートで次を実行する。

```powershell
dotnet build LocalHttpDaemon.slnx -t:Rebuild -c Debug
dotnet build LocalHttpDaemon.slnx -t:Rebuild -c Release
```

- Visual Studio 2026 からも、同じソリューションで両版をビルド・再ビルドする。
- 各アプリの Release ビルド・再ビルドで、Windows x64 向けの自己完結型単一 EXE と ZIP を自動生成する。配布先への .NET ランタイム導入は不要。ネイティブライブラリは実行時に一時展開される場合がある。
- CLI の EXE は `CLI_LocalHttpDaemon_Package/win-x64/CLI_LocalHttpDaemon.exe`、ZIP は `CLI_LocalHttpDaemon_Package/CLI_LocalHttpDaemon-win-x64.zip`。
- GUI の EXE は `GUI_LocalHttpDaemon_Package/win-x64/GUI_LocalHttpDaemon.exe`、ZIP は `GUI_LocalHttpDaemon_Package/GUI_LocalHttpDaemon-win-x64.zip`。
- ZIP には EXE と `README.md` のみを含める。CLI の README は `アプリケーション基本仕様.md`、GUI の README は `GUI版アプリケーション仕様.md` の複製とする。
- 配布物はビルド時に更新する。GUI の利用者設定 `settings.json` は上書きせず、ZIP に含めない。
- Debug ビルド、デザイン時ビルドではパッケージを生成しない。`-p:SkipReleasePackage=true` で自動生成を省略できる。
- ソース変更がない場合も Release ビルド時にパッケージを再生成する。

## 動作検証

```powershell
dotnet run --project CLI_LocalHttpDaemon_Verification -c Release -p:SkipReleasePackage=true
dotnet run --project GUI_LocalHttpDaemon_Verification -c Release -p:SkipReleasePackage=true
```

CLI 検証はルート未指定時のヘルプ・不正ポートの終了コード、HTTP / HTTPS の GET・HEAD・404・POSTの405、不正リクエストの400、GUI互換の設定保存・保存済み設定からの起動・引数の優先・HTTPのみの更新・ログ形式、子プロセス終了後のポート解放を確認する。実行環境を検証用フォルダにコピーし、配置先の既存設定は変更しない。検証終了時は起動した子プロセスを強制終了して片付けるため、Ctrl+Cによる正常停止の検証とは区別する。配布用 EXE の確認には次を実行する。

```powershell
dotnet run --project CLI_LocalHttpDaemon_Verification -c Release --no-build -- CLI_LocalHttpDaemon_Package/win-x64/CLI_LocalHttpDaemon.exe
```

GUI 検証は既存の画面・設定保存・HTTP / HTTPS・ログ・停止とポート解放の検証を引き継ぐ。GUI 検証実行時は一時的に検証用のウィンドウを表示する。

## 構成変更時の確認結果（2026-10-26）

- 統合ソリューションの Debug / Release リビルドは、4 プロジェクトとも警告 0・エラー 0 で成功。
- 両版の Release パッケージを生成し、各 ZIP に EXE と README のみが含まれることを確認。
- GUI の既存動作検証はすべて成功。
- CLI 配布用 EXE は HTTP の GET・HEAD・404・本文なし POST の405を確認。HTTPS は TLS ハンドシェイク時の予期しない EOF で失敗し、CLI 検証全体は終了コード 1。移動していない元の実装との比較検証は行っていない。
- CLI の本文付き POST の応答待ちと HTTPS の失敗は、今回のフォルダ整理・配布設定変更では修正していない。

## CLI機能追加時の変更（2026-10-26）

- CLIの設定保存はGUI版の `ServerSettings.cs` をリンクして共通利用する。CLI実行時にGUIアプリやWPFへの依存は追加しない。
- ログの結果確定・エラー記録に合わせて接続タイムアウトをGUI版と同じ30秒にし、本文が同時受信されたPOSTでもヘッダー終端を認識する。
- HTTPS検証で、一時キーがWindowsのTLS処理に対応せず接続が失敗する原因を確認した。CLIの証明書読み込みをGUI版と同じユーザーキーの永続化方式に変更する。
- Releaseビルドと配布用単独EXEでのCLI検証は成功。HTTP/HTTPS、設定保存・再読み込み・引数の優先・HTTPのみの更新、ログ形式、終了後のポート解放を確認した。ZIPはEXEとREADMEのみを含む。NuGet脆弱性情報の取得先に接続できずNU1900警告が発生したが、コンパイルエラーはない。
